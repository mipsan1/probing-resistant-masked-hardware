### 2.1 PROLEAD 실행 흐름 (1차 자료: PROLEAD/src/Hardware/Adversaries.cpp)

```
Execute::Execute()
  → Adversaries::Eval()                           (L1144-1168)
    → PrepareProbingSets(shared_data, n, sets_per_step, cycles)
                                                   (L1062-1142) ← step_idx 내부 loop
      → ProcessProbingSets(shared_data, step_idx)  (L972-1060)
        → EvalProbingSetsUnderFaults(...)          (L872-955)
          → EvalProbingSets(...)                   (L796-870)
            → PrintLeakageReport(...)              (L51-167) → leakages.json dump
      [next step_idx]
```

**각 step 완료 시 leakages JSON 1건 dump 후 다음 step으로 진행.**

### 2.2 가설 (가능성 順序)

| # | 가설 | 근거 | 심각도 |
|---|------|------|-------|
| **H1** | **OOM killer / swap-thrashing 종료** (~80%) | monitor.log: 잔여 메모리 6.1GB → 3.2GB steadily 감소. 각 step이 `probing_sets_.Initialize()`(ProbingSets.cpp:45)로 2M set × 28-76 byte contingency table = **수백 MB/step 추가 할당**. ProcessProbingSets 마지막 `probing_sets_.clear()`(Adversaries.cpp:1058)는 table만 해제. `signal_values_/register_values_/bitsliced probe values`는 영구 상주. WSL2 default 8GB + swap thrashing이 가장 확실 | 🔴 최상 |
| H2 | **OpenMP 중첩 region hang** (~15%) | `ProcessProbingSets`(L1053) `pragma omp parallel for Deconstruct`이 **이미 끝난** `EvalProbingSetsUnderFaults` 내부 OMP(L832, L932) 종료 후 들어감. macOS libomp + WSL gOMP 모두 nested-OMP 정책을 다르게 처리 | 🟠 보조 |
| H3 | **Boost::random thread_rng 누적** (~5%) | `EvalProbingSets`(L805) `GenerateThreadRng`로 thread당 mt19937 생성, 이후 매 sim 재초기화. 8 thread × 64 entry probing sets × 80k+ iteration | 🟡 가능 |
| H4 | shared_data race | `SharedData`가 thread 수만큼 복제 생성(Execute.cpp:28)되어 race 자체는 없음 | ⚪ 배제 |
| H5 | minimize="trivial" 루프 | `aggressive`는 robust 모드에서 warning 후 skip (L1044-1046). trivial은 sort+unique만(L981-985). 무관 | ⚪ 배제 |

**가장 가능성 높은 결론: H1 — resident memory 누적 OOM**. PROLEAD는 step boundary에서 disk write 후 OS가 죽이는 패턴.

### 2.3 즉시 적용 가능한 우회법 (3가지 옵션)

**Patch 2 (config-only, 리스크 0, 즉시 가능)**: `number_of_simulations=1200000`, `number_of_simulations_per_write=1200000` → PROLEAD가 1 step에서 종료, memory 누적 zero.

**Patch 3 (workaround script, 권장)**: `run_d2_full_resumable.sh`에 `ulimit -v 6G`, `OMP_NUM_THREADS=2` 추가.

**Patch 1 (소스 패치, ~5줄, 리스크 낮음)**: `Adversaries.cpp:1088` 부근에 env-driven step range 추가
```cpp

uint64_t start = step_start ? std::stoull(step_start) : 0;

if (step_idx < start) { /* skip */ }
if (step_idx >= end) return maximum_leakage;
```

### 3.1 기존 1차 자료 LEAK 시그니처 분석

6 batch × 64k sims = 384k sims에서 **20 LEAK 보고** → F6 수정 시 0-2 LEAK 예상 (90-100% 감소).

| 결과 | LEAK | false positive signature | F6 기여도 | F4 기여도 |
|---|---|---|---|---|
| fixB b0 | 0 | - | - | - |
| fixB b1 | 0 | - | - | - |
| **fixB_continue b0** | **4** | **단일 -log10(p)=5.3967936924909745 (소수점 16자리 일치), 4 모두 cycle 1 + 동일 ext 38** | **~75%** | ~10% |
| fixB_continue b1 | 0 | - | - | - |
| phaseC b0 | 0 (sub-step 32k-56k LEAK cluster) | sticky wire 3-step + 진동 + 사라짐 | ~80% | ~5% |
| **wsl2_b0** | **16** | **단일 -log10(p)=5.0672 plateau, 8/10 동일 anchor _002240_(2), sub-step 진동** | ~60% | ~10% |

**결정적 false positive signature**:
1. **단일 -log10(p) plateau**: fixB_continue b0의 4 LEAK가 **정확히 동일한 -log10(p) 값** (소수점 16자리 일치)
2. **동일 extension neighborhood**: 4 LEAK 모두 cycle 1 + 동일 ext 38
3. **단일 anchor wire**: wsl2_b0의 8/10이 동일 wire `_002240_(2)`
4. **sub-step 진동**: wsl2_b0의 8-step verdict = LEAK-OKAY-OKAY-OKAY-OKAY-LEAK-OKAY-LEAK (3/8 LEAK)

이 패턴들은 F6 expected_output 오류가 적용될 때의 **결정론적 false positive**로 정량화됨.

### 3.2 F4 (mask 재사용) 결함 가능성

**RTL 1차 자료 (rtl/masked_sbox_second_order.v:13-15, 437-445)**:
```verilog
q_01 = Reg(a₀·b₁ ⊕ r01)   q_10 = Reg(a₁·b₀ ⊕ r01)   // 동일 r01
q_02 = Reg(a₀·b₂ ⊕ r02)   q_20 = Reg(a₂·b₀ ⊕ r02)
q_12 = Reg(a₁·b₂ ⊕ r12)   q_21 = Reg(a₂·b₁ ⊕ r12)
c_0 = q_00 ⊕ q_01 ⊕ q_02   // 3-way 압축 (after barrier)
```

**Theorem (F4 안전성, PROLEAD의 cycle-resolved d-probing 모델 기준)**:
- `q_01 ⊕ q_10 = a₀·b₁ ⊕ a₁·b₀` (2nd-order term, r01 상쇄). 그러나 q_01과 q_10은 **물리적으로 다른 register** (서로 다른 위치). PROLEAD의 PerCycle probe는 단일 clock cycle의 단일 wire만 관찰 → q_01 또는 q_10 **각각 단독**으로는 1st-order AES (mask 1개 r01), d=2 attack에 **두 clock-cycle 데이터 동시 필요** → 모델 밖.
- 압축 register(mul1_0)는 3-way XOR 후 r01 ⊕ r02로만 mask → 1st-order 안전. d=2 attack은 mul1_0 ⊕ mul1_0'(다른 cycle) 같은 cross-cycle 조합 필요, 역시 모델 밖.
- **결론**: PROLEAD의 cycle-resolved glitch-extended probing 모델에서 F4는 **검출 불가능 & 비실 exploitable**.

**검출 시뮬 권장**: F4가 진짜 결함이면 q_01 단독 probe에서 1st-order AES 효과를 내므로 64k sims에 -log10(p) ~ 4-5 검출. 1.536M sims면 -log10(p) > 20. **현재 데이터로는 F4 검출/미검출 단정 불가**.
