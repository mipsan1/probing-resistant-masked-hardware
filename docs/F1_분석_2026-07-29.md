## 2. F1의 본질 — "시계열적 진화"의 증거

### 2.1 옛 RTL의 곱셈 코드 (barrier 없음)

`94623ed:rtl/masked_sbox_first_order.v`:
```verilog
// mul1 (옛 RTL, L240-243)
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) ... else if (v3) begin
    mul1_0 <= ((gf_mul_byte(x0_s1, x0_s2) ^ r0_in ^ r1_in) ^
               (gf_mul_byte(x1_s1, x0_s2) ^ r2_in ^ r3_in));
    mul1_1 <= ((gf_mul_byte(x0_s1, x1_s2) ^ r0_in ^ r1_in) ^
               (gf_mul_byte(x1_s1, x1_s2) ^ r2_in ^ r3_in));
  end
end
```

→ **두 곱셈 결과를 `^`로 즉시 결합** — cross-term (a0*b0) ^ (a1*b0) = b0*(a0^a1) = secret-dependent, **glitch-extended probe에서 LEAK**.

### 2.2 새 RTL의 곱셈 코드 (barrier 포함)

`d6308ea:rtl/masked_sbox_first_order.v`:
```verilog
// mul1 (새 RTL, L358-455, register barrier)
gf_mul_byte_mod u_m1_p00 (.a(x0_s1_d1), .b(x0_s2r), .y(m1_p00));
gf_mul_byte_mod u_m1_p01 (.a(x0_s1_d1), .b(x1_s2r), .y(m1_p01));
gf_mul_byte_mod u_m1_p10 (.a(x1_s1_d1), .b(x0_s2r), .y(m1_p10));
gf_mul_byte_mod u_m1_p11 (.a(x1_s1_d1), .b(x1_s2r), .y(m1_p11));

always @(posedge clk or negedge rst_n) begin
  if (!rst_n) ... else if (v3) begin
    mul1_q00 <= m1_p00;          // p_00 단독 저장 (cycle 3)
    mul1_q01 <= m1_p01 ^ r0_in;  // p_01 + r01
    mul1_q10 <= m1_p10 ^ r0_in;  // p_10 + r01
    mul1_q11 <= m1_p11;          // p_11 단독
  end
end

// 다음 사이클 (cycle 4): 압축
always @(posedge clk or negedge rst_n) begin
  if (!rst_n) ... else if (v4) begin
    mul1_0 <= mul1_q00 ^ mul1_q01 ^ mul1_q10 ^ mul1_q11;  // cycle 4에 압축
  end
end
```

→ 각 cross-term p_ij가 **개별 register에 저장**되고 **다음 사이클에 압축** — register barrier가 cross-term 결합을 막음.

### 2.3 1.536k LEAK의 wire 매핑

1.536k LEAK worst set:
- `_000503_(3)` (cycle 3, wire 503) — **옛 RTL의 mul1 결과** (cycle 3에 mul1_0, mul1_1이 register에 입력됨)
- `_000319_(3)`, `_000375_(3)`, `_000502_(3)` 등 — **옛 RTL의 곱셈 cross-term**
- extensions: `randomIn[25](2)`, `randomIn[17](2)`, `randomIn[9](2)` 등 — **glitch extension이 randomIn까지 propagate** (옛 RTL은 register barrier 부재로 마스크 비트가 곱셈 결과와 결합)

**1.536k LEAK는 옛 RTL의 register barrier 부재 + glitch extension이 randomIn까지 propagate한 결과.**

### 2.4 512k OKAY의 wire 매핑

512k worst set (모두 worst -log10(p) ≤ 3.39, 모두 OKAY):
- `_001065_(12)`, `_001065_(8)`, `_001065_(10)`, `_001065_(14)` (cycle 8~14, wire 1065)
- `_001191_(14)`, `_000939_(16)` (cycle 14~16, wire 1191)

→ wire 1065, 1191은 **새 RTL의 aff_inv, mul_inv 등 후반부 stage** (cycle 8~16). 새 RTL의 register barrier가 모든 곱셈 stage에서 LEAK 차단.

## 4. 1.536k LEAK가 진짜 결함인지 재평가

### 4.1 옛 RTL의 register barrier 부재의 의미

옛 RTL (`94623ed`)의 곱셈:
```verilog
mul1_0 <= ((gf_mul_byte(x0_s1, x0_s2) ^ r0_in ^ r1_in) ^
           (gf_mul_byte(x1_s1, x0_s2) ^ r2_in ^ r3_in));
```

cycle 3에서:
- `gf_mul_byte(x0_s1, x0_s2)` — 이 함수가 여러 cycle에 걸쳐 진행되는 조합 회로
- 결과가 register에 입력되기 전에 다른 곱셈과 XOR됨
- **glitch가 곱셈 중간 결과에 영향** → cross-term 누설

### 4.2 PROLEAD의 verdict

PROLEAD의 1.536k 결과:
- `number_of_leaking_probing_sets = 160` (2,816 중 5.7%)
- worst probe `-log10(p) = inf` (일부 wire, e.g., `_000503_(3)`)
- 1.536M sims는 검정력 99%로 **결정적 검출**

**1.536k LEAK는 옛 RTL의 진짜 결함** — register barrier 부재로 인한 cross-term glitch-extended probing 누설.

### 4.3 새 RTL의 register barrier가 진짜 해결책인지

새 RTL (`d6308ea`)의 곱셈:
```verilog
gf_mul_byte_mod u_m1_p00 (.a(x0_s1_d1), .b(x0_s2r), .y(m1_p00));
// ... (4개 곱셈 hard cell)
always @(posedge clk or negedge rst_n) begin
  if (v3) begin
    mul1_q00 <= m1_p00;  // p_00 단독 reg
    mul1_q01 <= m1_p01 ^ r0_in;  // p_01 + r01 reg
    mul1_q10 <= m1_p10 ^ r0_in;  // p_10 + r01 reg
    mul1_q11 <= m1_p11;  // p_11 단독 reg
  end
end
```

각 cross-term p_ij가 개별 register에 저장되고 다음 사이클에 압축. **PROLEAD의 robust d-probing 모델에서 SNI 만족**.

512k OKAY (worst -log10(p) = 3.39)는 새 RTL이 진짜 결함을 해결했음을 입증. **사용자(6855a66 커밋)가 이 verdict를 공식 기록**.

**왜 권고하나?**
- 512k sims는 17M probing set에 대한 검출 확률 90% (consensus 보고서 §2-F)
- 1.536k sims는 검출 확률 99% — TIFS 리뷰어가 1차 라운드에서 "왜 1.536k가 아닌 512k?" 라고 attack할 가능성

**왜 낮은 우선순위인가?**

- F4 (mask 재사용 결함) + F6 (expected_output 통일)이 d=2에 더 결정적 영향

**판단**: F1 후속으로 1.536k 재실행은 **nice-to-have, not must-have**. 대신 권고 1, 2, 3, 7 (문서화)을 우선.
