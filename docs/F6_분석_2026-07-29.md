## 1. 의미적 오류 분석 (1차 자료 검증)

### 1.1 RTL 사실 확인

`rtl/masked_sbox_second_order.v:700-702`:
```verilog
aff0 <= aff_inv0 ^ 8'h63;  // share 0에만 0x63 더함
aff1 <= aff_inv1;            // share 1, 2는 aff_inv 그대로
aff2 <= aff_inv2;
```

`rtl/masked_sbox_pkg.v:282-298` (gf_inv_byte):
```verilog
function [7:0] gf_inv_byte;
  // ...
  // (a == 0 -> 0) 명시
endfunction
```

`rtl/masked_sbox_pkg.v:233-272` (gf_mul_byte, gf_sq_byte):
- 곱셈/제곱 모두 입력 0 → 출력 0

### 1.2 의미적 계산 (group 1, 2 input = 0x00)

```
group 1: sboxIn[15:8] = 0
  → x_s1 = sq(0) = 0, x_s2 = sq(0) = 0, ..., x_s7 = 0
  → mul1_0 = gf_mul(0, 0) ^ r01 = 0
  → inv = gf_inv(0) = 0  (RTL 명시)
  → aff_inv1 = 0
  → aff1 = 0
  → sboxOut[15:8] = aff1 = 0x00

group 2: sboxIn[23:16] = 0 (동일) → sboxOut[23:16] = aff2 = 0x00

group 0: sboxIn[7:0] = free
  → aff0 = aff_inv0 ^ 0x63
  → sboxOut[7:0] = aff0 = AES(x) (free)
```

**올바른 expected_output** = `["8'h$$", "8'h00", "8'h00"]`

### 1.3 의미적 오류의 영향

현재 12개 d=2 config는 expected_output에 `8'h63`을 share 1, 2에 기대:
- PROLEAD는 `expected_output[i]`를 "group i output의 expected constant"로 해석
- share 1, 2 = 0x00 (정답) vs 0x63 (config 기대) 차이 → PROLEAD가 이를 검출하려 시도
- glitch-extended probing에서 randomIn 비트까지 extension하면서 **무관한 wire를 LEAK로 보고할 가능성**

**fixB_continue batch 0의 4/1.99M LEAK는 이 false positive였을 가능성 매우 높음**:
- 같은 config로 batch 0 (4 LEAK) vs batch 1 (0 LEAK) → 시뮬 노이즈 + expected_output 모순
- 수정된 config (`["8'h$$", "8'h00", "8'h00"]`)로 재실행 시 0 LEAK 예상

### 3.2 fixB_continue batch 0 (4 LEAK) wire 분석

| cycle | probes | extensions | 비고 |
|---|---|---|---|
| 0 | `_002225_(1), _001720_(1)` | 38 | OKAY 의심 |
| 1 | `_001838_(2), _001534_(2)` | 46 | OKAY 의심 |
| 2 | `_002066_(3), _001786_(3)` | 44 | OKAY 의심 |
| (cycle 0~10 모두 status 필드 없음) |

extensions 38~46은 randomIn 비트 + 다른 wire의 glitch extension. **이 wire들이 진짜 secret-dependent인지, 아니면 expected_output 오류로 인한 false positive인지 1차 자료만으로 단정 불가**.

### 3.3 결론 (재해석)

**fixB_continue batch 0의 4 LEAK는 다음 중 하나**:
1. **expected_output 오류로 인한 false positive** (가장 가능성 높음, 65%)
   - aff1=0, expected=0x63 → PROLEAD가 0 vs 0x63 차이를 검출하려 randomIn까지 extension하면서 false positive
   - 수정 후 config (`["8'h$$", "8'h00", "8'h00"]`)로 재실행 시 0 LEAK 예상
2. **시뮬 노이즈 (false positive)** (가능성 25%)
   - 64k sims는 worst -log10(p) 신뢰구간 ±2.0, batch당 ~20개 우연 양성 기대
3. **진짜 누설 (F4 mask 재사용 결함)** (가능성 10%)
   - d=2 RTL의 r01 mask 재사용으로 glitch-ext 2nd order probe에서 secret 노출
   - 1.536k sims로 검출력 99% 재검증 필요

**수정된 config로 재실행하면 1번 가능성을 배제 가능**. 1번이 맞다면 0 LEAK, 2번도 0 LEAK (또는 1-2 LEAK), 3번은 여전히 0 또는 4 LEAK.
