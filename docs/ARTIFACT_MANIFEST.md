# Artifact Manifest

**Paper**: Probing-Resistant Masked Hardware: Formal Security Proofs and
Simulation-Based Side-Channel Verification

**Purpose**: every number, table, and figure in the manuscript is mapped here
to the script that produced it, the input files it consumed, and the random
seed used. A reviewer should be able to go from any claim in the paper to a
reproducible command without guessing.

**Environment**: macOS (Apple Silicon, arm64), Yosys 0.67+, Python 3, PROLEAD
(built from source at `PROLEAD/release/PROLEAD`), Icarus Verilog. All commands
are run from the repository root.

## 0. Read this first: two different cell counts, both correct

The repository reports the gate count of the first-order design in two places
with two different numbers. They are **not** in conflict; they are counted
against different technology-mapping targets.

| Source | d=1 cells | d=2 cells | Mapping target |
|---|---:|---:|---|
| `syn/AREA_REPORT.md` | 43,268 | 78,148 | Yosys internal gate primitives (`$_AND_`, `$_MUX_`, ...) via `abc -fast` |
| Manuscript body, `lint_real.py`, `check_bypass_loops.py` | **77,587** | -- | `syn/prolead/library_yosys.json` custom cell library, as consumed by PROLEAD |

The custom PROLEAD library contains no complex cells, so multiplexers and other
compound gates present in the generic mapping (3,383 `$_MUX_` instances at d=1)
are decomposed into AND/OR/NOT. This inflates the cell count by roughly 1.8x
while describing the identical design.

**The manuscript quotes the PROLEAD-mapped counts** (76,771 combinational cells
+ 816 DFFs = 77,587 total), because those are the cells PROLEAD actually probes
and the cells the lint actually walks.

Design identity is fixed by the port declarations:

| Netlist | `sboxIn` / `sboxOut` | `randomIn` | DFFs | Order |
|---|---|---|---:|---|
| `syn/prolead/circuit_struct.v` | `[15:0]` (2 shares) | `[55:0]` | 816 | d = 1 |
| `syn/prolead/circuit_d2_struct.v` | `[23:0]` (3 shares) | `[151:0]` | 1,360 | d = 2 |

Invocation:

```
./PROLEAD/release/PROLEAD \
  --designfile=<netlist> --configfile=<config> \
  --resultfolder=<dir> \

```

PROLEAD writes its progress log to **stderr**, not stdout.

**Scope limitation of variant B.** The manuscript reports variant B on a
two-register loop-free subset, not on all 704 registers. Two facts force this.
First, bypassing a register can create a combinational loop: of 16 arbitrarily
chosen pipeline registers, 14 produced loops. The loop-free subset is computed
by `syn/prolead/check_bypass_loops.py --suggest N --out <file>` and recorded in
`prolead-modeB/design/modeB_dffs_safe.txt`. Second, removing registers
multiplies the number of glitch-extended probes; a 16 GB host peaks at 15.5 GB
on the two-register subset, which is the practical limit.

statements are superseded by "Update 2" at line 178. The CSVs in
`probe/results/d1/` are timestamped 21:40 and the summary file itself 21:56,
confirming the CSVs are the Update-2 outputs. **Use Update 2 and Update 3;
ignore the earlier warnings.**

**The structural pair, and why it is excluded.** The global 2-wire maximum is
1.020850 bits (MM 0.965667) at `y0_out[6] x y1_out[6]`, offset 18. This is not
residual leakage: at the module output boundary `y0 XOR y1 = Sbox(S)` by
definition, so any *correct* 2-share S-box exhibits it, and it appears at every
offset in the output-hold window 18--22. A d=1 adversary observes a single wire
and cannot form this pair. The security-relevant maximum excludes the eight
pairs `(y0_out[i], y1_out[i])` over offsets 18--22, leaving 12,895 tests and a
maximum of 0.062897 bits at empirical p = 0.91. Both values are printed in the
manuscript; the exclusion is stated in the body text and in the caption of
`tab:probing`.

## 4. Section VII-C -- partial second-order evaluation

Reported in the manuscript explicitly as a **partial** evaluation.

| Field | Value |
|---|---|
| Netlist | `syn/prolead/circuit_d2_struct.v` (1,360 DFFs, 3 shares, 152 mask bits) |
| Config | `syn/prolead/config_d2.json` (order 2, transitional leakage on) |
| Result dirs | `sim/prolead_d2_64k_fixB/`, `sim/prolead_d2_64k_fixB_continue/` |
| Standard probes | 25,536 (extended 29,184) |
| Order-2 space | 25,536 x 25,535 / 2 = **326,030,880** sets |
| Batch size | 2,000,000 requested; 1,997,984 after minimisation |
| Batches completed | **4** of approximately 163 -- coverage **~2.5%** |
| Simulations per batch | 64,000 |
| Wall time | ~1 h 17 m per batch; ~8.8 days for full coverage |
| Peak memory | 6 GB 984 MB (memory is not the constraint; time is) |
| Flagged sets | 0, 0, 0, 4 |
| Worst -log10(p) | 5.3967936924909745 at probes `_002225_(1)`, `_001720_(1)` |

**Why the four flags are false positives** (all three arguments appear in the
manuscript):

1. Bonferroni threshold at N = 1,997,984 and alpha = 0.05 is **7.6016**; the
   observation falls short by 2.2048.
2. The expected maximum -log10(p) under the null is log10(N+1) = **6.3006**; the
   observation is 0.9038 *below* pure-chance expectation. Expected false
   positives at p < 1e-5 is 19.98 per batch; four were seen.
3. In `fixB` batch 1 the progressive verdict reads LEAKAGE at 32,000 sims
   (5.190452), then OKAY at 48,000 (4.333737) and 64,000 (3.984851). Genuine
   leakage strengthens with traces; estimator noise flickers.

At d=1 the equivalent Bonferroni threshold is 5.4594, essentially equal to
PROLEAD's fixed threshold of 5 -- which is why the fixed threshold is safe at
first order and unsound at second order. The set-count ratio is 138.7x.

**Known issue.** `sim/prolead_d2_64k/` and `sim/prolead_d2_64k_fixA/` contain
crashed runs: PROLEAD's `expected_output` functional check fails
(`bit_index 4 ... Output value 16`) and the run aborts before writing a leakages
file. Those directories are excluded from the artifact.
